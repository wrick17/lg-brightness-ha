# Verification record

2026-09-27. This record separates the older recovery automation from the final 200 ms version in this repo.

Before the recovery change, the helper requested Medium while the TV was at Minimum. Choosing Medium again produced no helper state transition. After 78 seconds, the TV still read Minimum. The one-minute reconciliation in the recovery version later applied Medium without another slider change. All five settings produced matching physical `settings/getSystemSettings` readback during the older version's sweep.

The older recovery version passed three separate 35-second Home Assistant-to-TV TCP interruption cycles. Each time, the TV became unavailable, a request made during the interruption remained selected, and reconnection applied the requested value. The three requests were Maximum, Minimum, and Auto. Failure notifications cleared. The first Home Assistant restart exposed a dropdown `initial: Minimum` override; removing it restored native state restoration. Two later restarts retained Auto and Medium respectively, with matching TV readback.

The final version reduces helper debounce to 200 ms and removes a separate one-second wait before the first command. Only Off and Minimum were used for physical testing after that change. Two changes had command acknowledgements at 308 and 318 ms after the helper changed, and matching physical readback at 1,337 and 1,349 ms. These are Home Assistant-to-TV timings. The user separately reported that Apple Home felt noticeably quicker; no phone gesture-to-brightness timing was measured.

The final version passed three more separate 35-second Home Assistant-to-TV TCP interruptions. Requests Off, Minimum, and Off remained selected during their respective outages, applied after reconnection, and cleared failure notifications. A rapid sequence of 25%, 0%, 25%, 0%, 25% at 315–322 ms intervals settled at Minimum physically and in the helper. Two Home Assistant restarts retained Off and Minimum respectively, with matching TV readback, the webOS and HomeKit integrations loaded, and no LG failure notification. Temporary fault-injection rules were removed after each cycle.

Home Assistant configuration validation and the Script runtime regression passed for the version used in those live tests. A later code review found that the minute trigger's literal `on` guard could skip active `playing`, `paused`, or `idle` states. The public automation now treats those states as online. A Script runtime test reproduced the skipped `playing` state before the fix and passed after it. After deploying that guard, Home Assistant configuration validation returned no errors or warnings and the automation was reloaded. With the helper at Minimum and the physical TV deliberately set to Off, the minute trigger restored the TV to Minimum; its trace completed at 16:40:01.370 UTC and the failure notification cleared. The SSDP recovery check passed changed-host repair, device filtering, pairing-key preservation, and callback cleanup. The source patch is included here against a pinned upstream commit. The original router and Apple TV were not rebooted as part of these tests, so those complete restart paths remain untested.

2026-10-02. A new failure report had Apple Home slider changes reaching the helper while the TV integration was unavailable. Home Assistant history showed an approximately nine-minute unavailable interval covering those changes. The connection recovered before diagnosis completed; physical readback then matched the requested Off setting. Existing logs do not establish why the original connection stayed unavailable.

A separate, reproducible reconnect defect was found in the pinned `aiowebostv==0.9.2` client: a timeout connecting to the plain websocket port propagated without trying the secure port. A mock check failed on that path. A scoped live test dropped only the plain TV port for the Home Assistant user, reproduced the connection failure, and confirmed that the secure port could still read the physical setting. The temporary rule was removed after the test.

The patch now includes a small shared client subclass used by integration setup and the configuration flow. It adds timeout to the existing secure-port fallback conditions. Cancellation and failure of both ports still propagate. The patch applies cleanly to the same pinned upstream commit; no dependency or pairing changes were needed. The configuration, Script, SSDP, and new connection regression checks passed with Home Assistant Core 2026.1.3. The connection check covers timeout, rejection, handshake failure, plain-port success, both-port failure, cancellation, pairing-key preservation, and shared setup/pairing constructors. Independent review found no blocking issue.

The live integration was backed up before installing the three changed source files. Home Assistant configuration validation returned valid with no errors or warnings, and Home Assistant was restarted to load the Python change. The helper restored Off. With the plain TV port blocked, the LG integration reloaded successfully and three fan requests, Minimum, Off, Minimum, produced matching helper and physical readback in 0.75, 1.03, and 1.03 seconds. The test restored Off, verified physical Off, removed the temporary rule, and reloaded the LG integration again. These are Home Assistant-to-TV measurements; the iPhone gesture path was not measured. This fixes the confirmed timeout fallback defect, but cannot establish the cause of the earlier outage or guarantee recovery during a complete network failure.

A final live test interrupted both Home Assistant-to-TV ports, changed the fan to Minimum during the outage, and confirmed the request stayed selected while the physical TV remained Off. After removing the interruption, reconnection applied Minimum physically in 11.52 seconds without another helper change. Off was restored and physically verified. The user also confirmed that Minimum and Off both changed brightness from Apple Home after installation.

2026-10-02, regression prevention. The recovery code is now committed directly in the webOS override, so a HACS download retains the timeout fallback and SSDP callback. The setup guide pins the fixed source. The legacy patch is retained against its original commit and CI checks that it produces the same component as the fixed source.

Both repositories now have a GitHub Actions `regression` job on pushes and pull requests. The setup repository runs configuration, Script, connection, SSDP, and legacy-patch checks; the override runs connection, SSDP, and Core provenance checks. Main branch protection requires that job, including for administrators, and blocks force pushes and deletion. The connection regression exercises the actual setup, pairing, and reconnect callers as well as failure and cancellation paths. Deliberately removing the timeout fallback made the check fail; restoring it passed. Tests use the supported Home Assistant Core 2026.1.3 runtime with Python 3.13, aiowebostv 0.9.2, and async-upnp-client 0.46.1. They use fake responses and do not change a TV.
